# HWP 파싱 엔진 재설계

## 목표
기존 단일 파서의 정규식 분기를 계속 늘리는 대신, 원본 구조를 보존하는 공통 추출 코어와 템플릿별 어댑터를 분리한다. 문제 템플릿과 정답 템플릿은 독립적으로 판별한다.

## 템플릿 카탈로그 (현재 확인 범위)

### 문항 템플릿
| ID | 유형 | 구조적 특징 |
|---|---|---|
| Q-TABLE | 표 기반 | 행/셀 경계를 기준으로 문항이 배치됨 |
| Q-PREFIX | 선두 번호형 | 1., 1), 1번, Q1. 등이 문항 앞에 위치 |
| Q-SUFFIX | 후미 번호형 | 본문 뒤에 01, 02 등의 독립 번호가 위치 |
| Q-MIXED | 혼합형 | 객관식과 주관식/서술형 구역이 공존 |

### 정답 템플릿
| ID | 유형 | 구조적 특징 |
|---|---|---|
| A-INLINE | 내장형 | [정답], (답) 등 표식이 문항에 포함 |
| A-NUMBERED | 번호별 분리형 | 번호별 답안과 해설이 순서대로 배치 |
| A-PACKED | 묶음 정답표형 | 01 ⑤ 02 ③, ④처럼 여러 답이 한 줄/문단에 배치 |
| A-SUBJECTIVE | 주관식형 | 답이 숫자·문자열·식 등으로 기록 |

목록은 현재 확인된 샘플과 저장소 파서 동작에 한정한다. 모든 HWP 교재 유형을 망라한다고 가정하지 않는다.

## 파이프라인
1. Format Reader: HWP/HWPX를 읽어 원본 순서의 블록을 반환한다.
2. Core Extractor: 문단, 표/행/셀, 수식, 그림, 스타일, 원본 위치를 DocumentIR에 보존한다. 이 단계에서는 문항을 판별하지 않는다.
3. Template Detector: 문항 영역과 정답 영역을 독립적으로 분류하고 후보 점수와 경고를 반환한다.
4. Adapters: 선택된 문항/정답 템플릿을 각각 해석한다.
5. Assembler: 단원/문항 번호/원본 위치로 문제와 답안을 결합한다. 모호한 연결은 자동 확정하지 않는다.
6. Validator: 누락·중복·비정상 문항 및 연결 신뢰도를 검사한다.
7. Preview: 파싱 결과와 경고를 보여주고 사용자 검토를 지원한다.

## 설계 원칙
- 텍스트 평문화 전에 표/셀/인라인 객체 구조를 보존한다.
- 수식은 LaTeX뿐 아니라 원본 한컴 스크립트와 소스 위치를 보존한다.
- 그림은 자산 참조와 문서 내 위치를 보존한다.
- 문제 템플릿과 답안 템플릿은 조합 가능해야 한다. 예: Q-SUFFIX + A-PACKED.
- Detector는 추정값만 제공하며 원본 블록을 제거하거나 재배열하지 않는다.
- confidence가 낮거나 후보가 경합하면 경고와 사용자 검토를 요구한다.
- 원본 HWP는 회귀 fixture로 저장소에 추가하지 않는다.
